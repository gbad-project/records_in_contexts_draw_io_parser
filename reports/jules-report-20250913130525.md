# Revised Architectural Plan for P2T1: Decoupling the Draw.io Parser

**Date**: 2025-09-13
**Author**: Jules
**Task Reviewed**: P2T1 – XML to internal model
**Reason for Revision**: Initial plan did not adequately address the tight coupling of the legacy parser to the RiC-O ontology. This revision implements a new, ontology-agnostic architecture based on user feedback.

## 1. Objective

The objective is to create a robust, reusable Draw.io parser that is not dependent on any specific ontology. The parser's sole responsibility is to translate the visual structure of a Draw.io diagram into a generic data structure. This decouples the act of parsing from the act of validation and interpretation.

## 2. Analysis of Legacy System's Ontology Coupling

A targeted re-analysis of `draw_io_parser.py` confirmed that it was fundamentally coupled to the RiC-O ontology in several ways:
*   **Hardcoded Vocabulary**: The script contains extensive, hardcoded Python lists for RiC-O classes and properties (`_classes`, `_object_properties`, etc.).
*   **Embedded Validation**: The script validates parsed terms against these hardcoded lists during the parsing process, failing if a term is not recognized.
*   **Hardcoded Prefixes**: The `rico:` prefix is statically defined.

This design is brittle and not scalable. A simple port would inherit this technical debt.

## 3. New Decoupled Architecture

To address this, the implementation plan in `AGENTS.md` has been significantly revised. The new architecture is based on the principle of separation of concerns:

1.  **Ontology-Agnostic Parser (P2T1)**: The role of the Draw.io parser is now strictly limited to parsing the XML structure.
    *   It will extract all class and property identifiers (e.g., `"rico:RecordSet"`) as opaque strings.
    *   It will perform **no validation** against any vocabulary.
    *   The output is a generic representation of the diagram's nodes and arrows.

2.  **Prefix Expansion Utility (New Task P1T3)**: A new, separate utility will be created to handle CURIE expansion.
    *   This utility will take a user-defined mapping of prefixes to IRI bases (e.g., `{ "rico": "..." }`).
    *   It will provide a function to expand a CURIE into a full IRI.
    *   This utility can be used by any downstream module (like the P4 mapping engine) that needs to work with full IRIs.

## 4. Summary of Changes to `AGENTS.md`

*   **Added Task P1T3**: A new task, "P1T3 – Prefix Expansion Utility", was added to Phase 1 to provide a simple, configurable way to handle CURIEs.
*   **Revised Task P2T1**: The description for P2T1, "Ontology-Agnostic XML Parser", was completely rewritten to reflect the new, decoupled approach. The `AICODE-TODO` sub-tasks now guide the implementation of a generic parser, and the testing strategy focuses on validating the structural parsing against JSON snapshots, not against a specific ontology.
*   **Added `<!-- reviewed -->` tag**: The P2T1 task is now marked as architecturally reviewed.

This new plan ensures the TypeScript implementation will be more modular, reusable, and maintainable, avoiding the design flaws of the legacy system.
