## 2. Analysis of the End-to-End Workflow

The legacy workflow consists of a chain of Python scripts, each performing a distinct step:

1.  **`draw_io_parser.py`**: Parses a `.drawio` XML file into a Turtle RDF graph. It contains complex logic for interpreting the diagram's geometry and semantics.
2.  **`map_schema.py`**: Takes a schema definition and a source CSV file. It performs extensive, schema-specific preprocessing on the CSV data (splitting/merging columns, etc.) and then generates an RML mapping file that defines how to convert the CSV rows to RDF.
3.  **`map_rml.py`**: Executes the RML mapping using an external Java-based RML engine. It takes the RML file from the previous step and the preprocessed CSV to generate the main RDF graph. It also performs crucial post-processing, such as removing duplicate labels and merging supplementary schema triples.
4.  **`merge_graphs.py`**: Takes multiple RDF graph files and consolidates them into a single N-Quads file. It generates a unique, content-hashed named graph URI for each input file, ensuring that multiple conversion results can coexist in one dataset.

The new TypeScript application must replicate this entire sequence of operations within the browser, orchestrated by the React UI defined in `P7T1`.
