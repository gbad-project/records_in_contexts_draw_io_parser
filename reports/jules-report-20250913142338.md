# Architectural Report for P4T1: Mapping Model Definition

**Author:** Jules

**Associated Task:** `P4T1 – Mapping model`

## 1. Overview

This report details the architectural decisions for enriching the task description of `P4T1`. The goal of `P4T1` is to define a set of TypeScript interfaces that serve as a declarative, in-memory model for the CSV-to-RDF mapping process. This model replaces the legacy approach of generating an intermediate RML file.

My recommendations are based on a thorough analysis of the existing Python scripts (`map_schema.py` and `map_rml.py`) and the requirements of the downstream consumer task (`P4T2`).

## 2. Rationale for the Mapping Model Structure

The proposed `MappingModel` is designed to be a direct, type-safe representation of the logic currently embedded in the RML files generated by `map_schema.py`. By creating this model, we decouple the mapping definition from any specific file format (like RML) and make it a first-class citizen in the TypeScript application.

The structure is broken down into a hierarchy of interfaces: `MappingModel` -> `TriplesMap` -> `PredicateObjectMap` -> `ObjectMap`. This mirrors the structure of RML/R2RML and provides a logical way to represent the mapping rules.

### 2.1. `TriplesMap` Interface

This is the top-level container for mapping a single type of resource.

-   `id`: A unique identifier for the map. This is derived from the subject URI in the Draw.io diagram (e.g., `rr_template__KB_RecordSet__REFD_`) and is used for linking between maps (`parentTriplesMap`).
-   `rdfClass`: The `rdf:type` of the resource (e.g., `rico:RecordSet`). This comes from the `rr:class` declaration in the RML.
-   `subjectTemplate`: The template string for generating the subject URI (e.g., `/KB/{HEADING}`). This directly corresponds to the `rr:template` value in a `rr:subjectMap`.
-   `logicalSource`: Specifies the data source. For now, it's just the path to the CSV, as seen in the `rml:logicalSource` of the RML.
-   `condition`: This field is crucial for replicating the conditional generation logic implemented using FnO in `map_schema.py`. It allows the mapper to check if a certain column has a value before generating the resource.
-   `predicateObjectMaps`: An array of `PredicateObjectMap`s, representing the properties of the resource.

### 2.2. `PredicateObjectMap` Interface

This interface represents a single property of a resource.

-   `predicate`: The URI of the RDF predicate (e.g., `rdfs:label`). This corresponds to the `rr:predicate` in an RML `rr:predicateObjectMap`.
-   `objectMaps`: An array of `ObjectMap`s. This is an array because a single predicate can have multiple ways of generating objects (e.g., from different columns or using different templates).

### 2.3. `ObjectMap` Interfaces (Polymorphic)

This is a set of interfaces to represent the different ways an object can be generated. This design is directly inspired by the different `rr:*` properties that can be used in an `rr:objectMap` in RML.

-   `ReferenceObjectMap ({ type: 'reference' })`: Corresponds to `rml:reference`. It specifies a `column` in the CSV from which to draw a literal value.
-   `TemplateObjectMap ({ type: 'template' })`: Corresponds to `rr:template`. It provides a `template` string with placeholders (e.g., `{TITLE}`) to generate a literal or URI.
-   `ConstantObjectMap ({ type: 'constant' })`: Corresponds to `rr:constant`. It provides a fixed `value`.
-   `ParentTriplesMapObjectMap ({ type: 'parentTriplesMap' })`: Corresponds to `rr:parentTriplesMap`. This is essential for creating links between resources (joins). It contains the `id` of the parent `TriplesMap` to link to.

## 3. Connection to Legacy Python Scripts

-   The logic within `map_schema.py` that parses the Draw.io graph and generates RML triples is the direct source of inspiration for the `buildMappingModel` helper function that will create this new `MappingModel`.
-   The `uriref_str_to_map` function in `map_schema.py` is the key piece of logic that will be ported to create the different types of `ObjectMap`s based on the text found in the Draw.io nodes.
-   The use of FnO for conditional generation in `map_schema.py` is the reason for including the `condition` property in the `TriplesMap` interface.

By defining this model, we are essentially creating a structured, type-safe "AST" (Abstract Syntax Tree) for the mapping, which the TypeScript mapping engine in `P4T2` can then execute. This is a much more robust and maintainable approach than manipulating RML strings.
